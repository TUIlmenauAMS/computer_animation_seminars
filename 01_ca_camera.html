1. Camera Animation

In computer animation, the camera is not a special object — it is just another object in the scene with a position and orientation that can be keyframed, interpolated, and eased. The only thing that makes it the camera is that its transform is used to build the view matrix passed to the GPU.

The lookAt function constructs this view matrix from three values: the eye position (where the camera is), the target point (what it is looking at), and an up vector (which way is up in the camera's frame). Animating eye and target over time is all that is needed to produce a camera move.

This demo shows three common camera animation patterns: orbit (circular arc around a fixed point, defined by spherical coordinates), dolly (linear path between two positions, with easing from Demo 2), and look-at lerp (interpolating between two fully defined cameras to produce a blend or a cut).

3. How It Works

The script follows the same nine-step structure as Demos 1 and 2. Steps 1–5 are WebGL setup and geometry. The camera animation concepts are in Steps 6–8.

Step 6 defines the three camera modes as pure data: spherical-coordinate parameters for orbit, two endpoint vectors for dolly, and two camera definitions (eye + target) for look-at lerp. Step 7 wires the UI sliders. Step 7b wires canvas drag, touch and scroll events. Step 8 computes the current eye and target each frame for the active mode, then calls mat4.lookAt exactly once to produce the view matrix.

All three modes converge on the same two values — eye and target — and use the same mat4.lookAt call. This is the key insight: any camera move is just a path through (eye, target) space.

Canvas interaction (Step 7b): Dragging on the canvas writes to the same state variables the sliders already control — the canvas never owns state. Drag events push new values through the slider elements using a synthetic input event, so the slider badges always stay in sync. In orbit mode, horizontal drag changes azimuth and vertical drag changes elevation; scroll changes radius. In dolly and lookAtLerp modes, horizontal drag scrubs the animation parameter t forward and backward.

Connections to professional tools: Blender and Maya expose exactly these same parameters on their camera objects. The orbit control is the same math used in Three.js OrbitControls. The cubic Bézier easing from Demo 2 can be dropped into the dolly mode with zero changes — easing is just a function f(t) → t' applied before the lerp. After Effects uses the same lookAt-equivalent when you parent a camera to a null object and animate the null.
