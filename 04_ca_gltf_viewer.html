Demo 1: glTF Viewer

The entry point for Seminar 04. This demo loads Fox.glb — a fully rigged, animated character from the Khronos glTF Sample Assets — using GLTFLoader and displays it in a Three.js scene with hemisphere lighting and OrbitControls.

After the model loads, open DevTools → Console and inspect the gltf object that is logged there. You will find gltf.scene (the Three.js scene graph), gltf.animations (three named AnimationClips: Survey, Walk, Run), and gltf.asset (version metadata). The asset report panel on the right is built from the same data — it shows exactly what the loader hands you.

THREE.JS CONCEPT — importmap
This demo uses a <script type="importmap"> block to tell the browser how to resolve bare module specifiers like 'three' without a bundler. This is how modern Three.js is used with plain HTML — no Webpack or Vite needed.
GLTF CONCEPT — gltf.scene
gltf.scene is a THREE.Group containing the entire glTF scene hierarchy. Every mesh, bone node, and camera from the .glb file is a descendant of this group. Calling scene.add(gltf.scene) integrates the whole asset into the Three.js world in a single call.
ANIMATION CONCEPT — renderer.outputColorSpace = THREE.SRGBColorSpace
glTF 2.0 mandates that all colour textures are stored in sRGB colour space. Three.js must apply an sRGB-to-linear conversion when displaying them, or colours appear washed out and flat. Setting outputColorSpace enables this — it is the same gamma correction problem as in offline rendering, solved here automatically by the renderer.
