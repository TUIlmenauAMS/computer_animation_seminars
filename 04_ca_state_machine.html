Demo 3: Locomotion State Machine

A locomotion state machine drives animation transitions automatically from a single parameter: the character's speed. Drag the speed slider and watch the state machine decide which clip to play — Idle, Walk, or Run — and crossfade between them at the configured thresholds, with no manual clip buttons needed.

This is exactly what Unity's Animator Controller and Unreal's Animation Blueprint do automatically. Here you build the logic by hand so you can see every piece. Switch between three characters to verify the same state machine code drives any rigged glTF. Open DevTools → Console to see every state transition logged.

ANIMATION CONCEPT — What is a locomotion state machine?
A locomotion state machine maps a continuous parameter (here: speed in m/s) to a discrete set of animation states (Idle, Walk, Run) and automatically fires crossFadeTo() when the parameter crosses a threshold. Unity's Animator Controller, Unreal's Animation Blueprint, and Godot's AnimationTree all implement this same pattern visually — what you are building here by hand is exactly the logic those tools generate from the graph editor. The parameter-driven state machine is the foundation of every locomotion system in every game engine.
THREE.JS CONCEPT — crossFadeTo(nextAction, duration, warp)
currentAction.crossFadeTo(nextAction, fadeDuration, true) simultaneously fades out the current action and fades in the next one over fadeDuration seconds. The warp: true argument additionally scales the time of each action so that clips of different durations stay aligned during the fade — without it, a short idle clip and a long run clip would fall out of sync mid-transition. The live Action Weights panel shows both weights summing through 1.0 during a crossfade, then settling as one action reaches weight 0 and is stopped automatically by the mixer.
ANIMATION CONCEPT — Clip portability
An AnimationClip is a list of KeyframeTracks, each identified by a string like "Spine.quaternion". The mixer matches track names to Object3D.name values in the scene graph. This means any clip exported for a skeleton can play on any other character that has bones with the same names. Fox, Knight, and Barbarian each have differently named bones — but the same state machine code drives all three. Switch models and verify: the thresholds, the transition logic, and the crossFadeTo call are identical. Only the clip names in the registry differ.
